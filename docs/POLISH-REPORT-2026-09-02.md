## 6. Lessons

Each class of mistake from this audit, why it happened, and the rule going forward (also appended to SKILL.md Pitfalls so the Monday run inherits them):

- **Reading state from the wrong lifetime (D-4).** The builder read a week-scoped file (`draft.json`) to render permanent artifacts, so every old edition silently depended on _this_ week's data surviving. Rule: anything week-scoped must be persisted into the artifact it describes at creation time; builders read only edition-local state. Test by removing the volatile file and rebuilding.
- **Building CSS without a scale (C-1/C-2/C-11).** 42 font sizes and 40 stray hexes weren't one bad decision — they were 100 small unreviewed ones, each locally reasonable. Rule: named tokens first (`:root`), literals are a lint failure; when a value is new, add a token or reuse one, never type a number.
- **Positioning badges without checking overlap (R-1/R-2).** Absolute positioning over flexible content means overlap is a _when_, not an _if_ — the 38-char guard was a guess about a font's width. Rule: overlays get measured (Playwright bounding-box intersection), not estimated; the guard lives in qa, not in the reviewer's eye.
- **Deploying with cp instead of rsync (D-5).** `cp -r` can only add, so retired pages are immortal and nobody notices because the old URL still works. Rule: deploys are `rsync --delete` (or equivalent) so the destination is a function of the source, and the deletion is verified by curling a retired URL expecting 404.
- **Trusting a structural QA gate for visual bugs (D-8).** qa.py counted sleeves and modals, so it passed every layout bug on the live site. Rule: every visual bug fixed gets a cheap structural proxy check in the same PR (lane presence, note length, class presence) — the gate can't see pixels, but it can count the conditions that produced the bug.
- **Writing rules in prose that no code checks (S-5..S-8).** Caps, cooldowns, and repeats all existed on paper and all were broken in week 2, because the only enforcer was a model's memory. Rule: a rule that matters gets a mechanical enforcer that says _no_ (exit nonzero, state untouched); prose documents the rule, code applies it.
- **Letting a theme wheel run without intent (S-1).** The wheel named scenes but never decided what _shape_ each week's story takes, so every scene defaulted to four ProgArchives catalog picks. Rule: every rotation entry carries an explicit intent (mode + angle) that drives harvest, rendering, and is recorded on publish — defaults are decisions too, so make them once, explicitly.
